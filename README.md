# MESH Assistant

Веб-приложение для задач:
- аналитика по отметкам/рискам учеников;
- массовая проставка отметок (через API учителя, с предпросмотром).
- рассылки личных сообщений через собственный аккаунт Telegram, независимо от МЭШ.

## Архитектура

- Фронтенд разбит на модули и компоненты (`web/js/*`).
- Используется Vite для разработки и сборки.
- Бэкенд (`web-service.js`) отвечает за:
  - статику;
  - `/api/config`;
  - прокси `/api/mesh` -> `https://school.mos.ru/api/...`.
- Авторизация хранится в браузере (`localStorage`): `token`, `profile_id` (+ role/host/aid).

## Рассылки в Telegram

На главном экране выберите «Рассылки». Вход в МЭШ для этого не нужен.
Подключите Telegram по номеру телефона, коду подтверждения и, если включена
двухэтапная аутентификация, паролю. Проверка email, регистрация нового аккаунта
и дополнительные CAPTCHA-проверки Telegram пока не поддерживаются: приложение
показывает ошибку и не пытается обходить эти проверки.

Создайте группу, через «+ Контакты / изменить» выберите людей из ваших контактов,
напишите сообщение и отправьте. Получатели и текст видны перед отправкой.
Группа — внутренний список рассылки, новый чат Telegram не создаётся.
Изменение группы не меняет уже запущенную рассылку.

### Настройка сервера

1. Получите собственные `api_id` и `api_hash` в
   [Telegram API development tools](https://my.telegram.org/apps).
2. Заполните `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в `.env` (пример — `.env.example`).
3. Перезапустите сервер. Без этих параметров остальные разделы работают,
   а «Рассылки» показывают инструкцию по настройке.

Используется поддерживаемый MTProto-клиент `teleproto`. Подключение — полноценная
сессия пользовательского аккаунта, не Bot API и не Telegram Login Widget.
Для удалённого доступа нужен HTTPS; локально можно использовать localhost.
Не публикуйте этот личный инструмент как открытый сервис без контроля доступа
на reverse proxy. Запускайте один процесс сервера на одно хранилище Telegram.

Если вход долго ждёт и заканчивается ошибкой соединения, проверьте именно
исходящий доступ **с сервера/контейнера** к Telegram. Доступность обычных сайтов
не означает доступность Telegram. Ошибка подключения возникает до проверки
`api_id`/`api_hash`; замена этих значений сетевой таймаут не исправляет.

Для сервера, которому нужен SOCKS5-прокси, задайте в `.env`:

```dotenv
TELEGRAM_PROXY_URL=socks5h://user:password@your-proxy-host:1080
```

Как в school-crm, поддерживаются `socks5://` и `socks5h://`, хост и порт обязательны.
Без аутентификации: `socks5h://your-proxy-host:1080`. Пустое значение оставляет
прямое подключение. Спецсимволы в логине и пароле нужно URL-кодировать:
например, `@` → `%40`, `#` → `%23`. Не публикуйте URL с паролем.
Для Docker `127.0.0.1` означает сам контейнер, а не хост.
После изменения `.env` пересоздайте только контейнер приложения:
`docker compose up -d --build mesh-assistant`.
Прокси передаётся в MTProto-клиент явно: `HTTP_PROXY`/`HTTPS_PROXY` сами по себе
для него не подходят.

По умолчанию (`TELEGRAM_TRANSPORT=auto`) с прокси используется MTProto через
защищённый WebSocket к `*.web.telegram.org:443`. Это помогает, когда прокси
пропускает домены Telegram, но не прямые IP дата-центров. Используйте `socks5h://`,
чтобы DNS-имя разрешал сам прокси; `socks5://` использует DNS сервера приложения.
Без прокси сохраняется прямое TCP-подключение. При необходимости можно явно
выбрать `TELEGRAM_TRANSPORT=tcp` или `wss`. TLS-сертификаты проверяются.

Каждая операция Telegram ограничена 20 секундами (подключение и запрос кода
вместе — до 40 секунд). При таймауте соединение закрывается; автоматически новый
код не запрашивается. Браузер прекращает ожидание через 50 секунд даже при
зависшем сервере или reverse proxy. Если таймаут случился при запуске рассылки,
нужно сначала проверить историю: запрос мог успеть запустить отправку.

### Хранение

- `localStorage`: непрозрачный токен доступа к разделу (до 30 дней) и группы
  под ключом `telegram_groups_v1_<account_id>`. Группы разделены по аккаунтам;
  после выхода сохраняются, после очистки данных браузера теряются.
  Между браузерами и устройствами они не синхронизируются.
- Сервер: сессии Telegram и последние 20 рассылок каждого аккаунта с текстами,
  получателями и результатами. Хранилище `.telegram-data/state.enc` зашифровано
  AES-256-GCM. При первом входе создаётся ключ `.telegram-data/key` с правами `0600`.
  Код входа и пароль не сохраняются. Полная сессия Telegram не передаётся браузеру.
- Для отдельного хранения ключа задайте `TELEGRAM_SESSION_KEY` — 32 случайных байта
  в base64. Ключ нельзя менять без миграции/сброса хранилища.
  Шифрование с ключом рядом с файлом не защищает от компрометации самого сервера.
  Браузерный токен также является секретом: владелец токена получает доступ к разделу.
- `TELEGRAM_DATA_DIR` переопределяет каталог. Он должен находиться вне `web/`.
  В Docker Compose подключён постоянный том `telegram-data`; сессии не теряются
  при пересоздании контейнера. Каталог исключён из Git и Docker build context.
- «Выйти из Telegram» отзывает соответствующую Telegram-сессию и удаляет токен
  браузера. Если сессия уже отозвана в Telegram, приложение попросит войти снова.

### Очередь и ограничения

Отправка идёт последовательно с интервалом `TELEGRAM_SEND_INTERVAL_MS`
(по умолчанию 30 секунд, минимум 5 секунд). Это ограничение скорости приложения,
**не гарантированная безопасная квота Telegram**. Наличие человека в контактах
само по себе не означает, что он ожидает рассылку. Перед запуском пользователь
подтверждает ожидаемость сообщений.

На аккаунт допускается одна незавершённая рассылка, до 100 получателей.
Браузер можно закрыть: очередь работает на сервере. «Остановить» отменяет ещё
не начатые отправки; сообщение, уже переданное Telegram, может быть отправлено.
`FLOOD_WAIT` сохраняет обязательную паузу на уровне аккаунта, после которой
нужно вручную продолжить очередь. Новая рассылка и повторный вход не сбрасывают
эту паузу. При `PEER_FLOOD`/ограничении аккаунта отправка останавливается.
После проверки через @SpamBot и снятия ограничений используйте «Ограничения сняты»;
эта кнопка снимает только локальную остановку и ничего не меняет в Telegram.

Повтор одного запроса защищён идентификатором рассылки; у каждого сообщения
сохранён Telegram `random_id`. После сетевой ошибки с неизвестным результатом
автоматической повторной отправки нет. Статус «результат неизвестен» требует
проверки диалога. После перезапуска сервера незавершённые очереди приостановлены,
начатые, но не подтверждённые сообщения помечены как неизвестные.
«Продолжить оставшиеся» отправляет только ещё не начатые сообщения.
Статус «Отправлено» означает принятие Telegram, а не прочтение адресатом.

Официальные ограничения: [Telegram Spam FAQ](https://telegram.org/faq_spam),
[использование API](https://core.telegram.org/api/obtaining_api_id),
[обработка FLOOD_WAIT](https://core.telegram.org/api/errors).

## Запуск

### Продакшен-режим (без Vite)

```bash
npm install
npm run start
```

Открыть: [http://localhost:8787](http://localhost:8787)

### Режим разработки (Vite + автообновление)

```bash
npm install
npm run dev
```

Открыть: [http://localhost:5173](http://localhost:5173)

## Где взять token/profile_id

1. Войти в [school.mos.ru](https://school.mos.ru).
2. DevTools -> Console.
3. Вставить команду:

```js
(() => {
  const session = JSON.parse(localStorage.getItem('sessions') || '{}');
  const teacher = session.profiles?.find((p) => p.type === 'teacher') || session.profiles?.[0];
  console.log(JSON.stringify({
    token: session.authentication_token,
    profile_id: teacher?.id
  }, null, 2));
})();
```

4. Скопировать JSON из консоли в поле `Token`. `profile_id` заполнится автоматически.

Можно также скопировать значение ключа `sessions` целиком и вставить его в поле `Token`: приложение само возьмет `authentication_token` и teacher-профиль.

## Docker

Сборка:

```bash
docker build -t mesh-assistant .
```

Запуск:

```bash
docker run --rm -p 8787:8787 mesh-assistant
```

Или через Docker Compose:

```bash
docker compose up -d --build
```

Остановить:

```bash
docker compose down
```

## Источники данных

- `Аналитика`: автоматически определяются доступные классы, есть выбор класса в UI.
- Для совместимости можно задать `API_CLASS_UNIT_IDS` (через запятую), тогда аналитика фиксируется по этим классам.
- `Проставить отметки`: группы учителя (`assigned_group_ids`).

## Диагностика загрузки групп

После обновления страницы откройте DevTools -> Console, задайте фильтр
`[MESHhelper]` и запустите аналитику. Строки `API discovery` показывают
формат ответа, названия полей, количество групп и ID запрошенного учебного
года. Строка `Analytics groups` показывает число обычных групп и метагрупп,
а также количество нулевых и неизвестных счётчиков учеников.
`student_count` не используется для исключения групп: даже при нулевом
значении у группы могут быть отметки за выбранный период. Метагруппы
учитываются через связи с обычными группами.

Запрос учеников ограничен выбранным учебным годом и классами/группами;
архивные группы, переведённые и удалённые профили не включаются.
Строка `Analytics data` показывает количество полученных профилей,
отметок, отметок без соответствующего профиля и строк отчёта.

Список учеников формируется по составу класса, включая учеников без
отметок и пропусков. Записи общих групп, не сопоставленные с профилями
выбранного класса, не создают дополнительных учеников с именем `ID …`.
Сохранённый фильтр скрытых учеников продолжает действовать;
флажок «Показывать скрытых» отображает их без удаления настроек скрытия.

Аналитика использует только `API_ACADEMIC_YEAR_ID` и диапазон
`EXPORT_START_AT`–`EXPORT_STOP_AT` из настроек сервера. Пустой ответ
не переключает приложение на прошлый год и не запускает загрузку
карточек старых назначений. Классы ищутся также по `managed_class_unit_ids`
профиля и общему списку групп за выбранный год. Если их нет, загрузка
выдаёт ошибку с ID запрошенного года. Строка `Analytics period` показывает
год и диапазон дат запроса отметок.

Заголовок `aid` прокси формирует из `academic_year_id` запроса или
`API_ACADEMIC_YEAR_ID`, в том числе для запросов профиля учителя без
параметра года. Он не берётся из сохранённой авторизации или `API_AID`.
Поле `requestAcademicYearId` в `API discovery` показывает отправленный
в заголовке год, а `responseAcademicYearId` — год из ответа МЭШ.

Для разбора ошибки достаточно скопировать эти строки. Они не содержат
токенов, ФИО или значений идентификаторов профилей. Если API изменился,
полезен также свежий запрос списка групп из рабочего журнала МЭШ:
путь, параметры учебного года и обезличенная структура ответа.
Не публикуйте необработанный HAR: заголовки, cookies, тела запросов
и ответы могут содержать токены и персональные данные.
